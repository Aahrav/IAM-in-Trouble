# **🚨 Kiro Agent Master Specification: "IAM In Trouble"**

**Project Name:** IAM In Trouble (Alternative: "Who Let The S3 Out?")

**Tagline:** *Because waking up at 2:00 AM to a $40,000 AWS bill is not a vibe.*

**Target Environment:** Local Ubuntu/WSL Terminal

**Development Timeframe:** 4-Hour Hackathon Sprint

## **🎯 1\. Project Context & Philosophy**

### **What is it?**

A terminal-based escape room simulating an actively unfolding AWS security incident at 2:00 AM. The player acts as an on-call SRE who must use real AWS CLI commands to secure the account before a live "Bankrupt Counter" drains the company's fake bank account.

### **Why are we building this? (The Problem/Solution)**

Junior developers and students are terrified of AWS billing surprises. The fear of leaving a GPU instance running prevents them from practicing cloud architecture. This project provides a 100% risk-free, highly gamified environment to build authentic AWS CLI muscle memory.

### **Core Agentic Constraints (Strict Rules for Kiro)**

1. **NO WEB UI:** Do not generate HTML, React, or CSS. The entire application lives inside a standard Bash terminal.  
2. **AUTHENTIC CLI:** Players must use authentic AWS CLI syntax targeting a local endpoint.  
3. **MOCK BACKEND:** All cloud infrastructure is simulated locally via Docker \+ LocalStack Community Free Edition.

## **🛠️ 2\. Tech Stack & Required File Structure**

* **Cloud Backend:** Docker \+ LocalStack (port 4566\)  
* **Game Engine:** Python 3 \+ boto3  
* **Terminal Theater:** Bash \+ ASCII Art \+ ANSI Escape Codes

### **Target Directory Structure**

/iam-in-trouble  
├── setup.py               \# Spawns the hacked resources in LocalStack  
├── verify.py              \# Evaluates player actions via boto3/JSON parsing  
├── start\_game.sh          \# UI shell: Renders the intro and spawns the live ticker  
├── briefing.sh            \# UI shell: Dumps the narrative context  
├── verify.sh              \# Wrapper: Passes level arguments to verify.py  
└── attacker\_policy.json   \# (Generated by setup.py) The broken IAM file for Level 3

## **🚀 3\. Implementation Phases (Step-by-Step Logic)**

### **Phase 1: Environment Prep & Backend Setup**

* **What:** Initializing the LocalStack API gateway and configuring the local AWS CLI.  
* **How:**  
  * Docker container spun up via docker run \-d \-p 4566:4566 localstack/localstack.  
  * AWS CLI configured with dummy credentials (test/test).  
  * All AWS CLI calls must append: \--endpoint-url=http://localhost:4566.  
* **Why:** We must intercept standard AWS API calls and route them locally so we can evaluate CLI commands without spending real money.

### **Phase 2: The Python Game Engine (setup.py & verify.py)**

* **What:** The boto3 logic to create the "hacked" state and check the player's fixes.  
* **How:**  
  * **Level 1 (EC2 \- "The Crypto Miner"):**  
    * *Setup:* Use boto3.client('ec2') to spawn a p4d.24xlarge instance.  
    * *Verify:* Use describe\_instances to assert the instance state is "terminated".  
  * **Level 2 (S3 \- "Who Let The S3 Out?"):**  
    * *Setup:* Use boto3.client('s3') to create bucket customer-passwords-do-not-share and apply public-read ACL.  
    * *Verify:* Call get\_bucket\_acl and parse the Grants list to ensure public access is fully revoked.  
  * **Level 3 (IAM \- "IAM In Trouble"):**  
    * *Setup:* Use standard Python file I/O to generate attacker\_policy.json locally containing an explicit "Effect": "Deny" on a payroll database.  
    * *Verify:* Bypass LocalStack for this step. Build a lightweight Python JSON parser that reads the local file and verifies the "Deny" block has been manually deleted by the player.  
* **Why:** Using Python as the validation engine provides robust, programmatic evaluation of the cloud state, rather than relying on brittle Bash string matching.

### **Phase 3: Terminal Theater (The Bash UI)**

* **What:** The immersive, high-stakes visual environment running natively in the terminal.  
* **How:**  
  * **The Bankrupt Counter:** A Bash while loop that increments a financial variable (e.g., $32.50...). It uses ANSI escape codes (\\033\[s to save cursor, \\033\[1;80f to move to top right, \\033\[u to restore) to print in the corner. **Crucial:** Execute with & to run asynchronously so it does not block the player's CLI input.  
  * **start\_game.sh:** Echos retro ASCII art (PagerDuty Alert) and triggers the background counter.  
  * **briefing.sh:** Prints the narrative backstory of the leaked API key and the crypto miner.  
  * **verify.sh:** Takes user input (e.g., ./verify.sh 1\) and passes it to python3 verify.py 1\. If Python returns an exit code of 0 (Success), Bash prints the ASCII "Victory Screen".  
* **Why:** The asynchronous Bash loop delivers psychological urgency (the ticking money) without the need for a web browser, keeping the developer fully immersed in the raw terminal environment.

### **Phase 4: Integration & Polish**

* **What:** End-to-end integration testing of the Bash wrappers calling the Python engine.  
* **How:** Run ./start\_game.sh, execute standard aws \--endpoint-url... commands, edit the JSON in nano, and run ./verify.sh for each level. Ensure reaching Level 3's victory kills the background Bankrupt Counter process (using kill $\!).  
* **Why:** A hackathon demo must be seamless. Hanging background processes or unlinked scripts will ruin the live presentation.

### **Phase 5: The Live Demo Execution**

* **What:** The final presentation to the hackathon judges.  
* **How:**  
  1. Hook judges with the 2:00 AM PagerDuty narrative.  
  2. Run ./start\_game.sh to trigger the live ticking money drain.  
  3. Live-type the aws CLI commands to fix the issues, demonstrating 100% real CLI muscle memory targeting the mock backend.  
  4. Run the final verify to trigger the "Promoted to Senior SRE" ASCII victory screen.  
* **Why:** Judges suffer from demo fatigue. This high-energy, visually striking terminal game, grounded in a real-world developer pain point (cloud billing), is designed to immediately capture attention and demonstrate technical competence.
